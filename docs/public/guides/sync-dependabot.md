# Sync Dependabot

`dependabot.yml` is not inherited from an org `.github` repo — GitHub only inherits issue and
pull request templates and a few other files. So each repo carries its own, generated by
`scripts/sync-dependabot.sh`.

```bash
./scripts/sync-dependabot.sh --dry-run /path/to/repo   # print what it would write
./scripts/sync-dependabot.sh /path/to/repo             # write .github/dependabot.yml
```

## What it generates

The policy is **security-only**:

- `open-pull-requests-limit: 0` on every entry — no routine version-update pull requests.
- Security-update pull requests still flow (they are exempt from the limit), but
  `version-update:semver-major` is ignored, so only patch and minor fixes open a pull request.
  A fix that needs a major shows up as a Dependabot alert and an OSV warning in CI, and is done
  by hand.

It detects what to cover:

| Found | Entry |
|---|---|
| always | `github-actions` at `/` |
| a directory with `Dockerfile` or `Dockerfile.*` | one `docker` entry per directory |
| a directory with `package.json` | one `npm` entry per directory |
| any dependency on `@skylabs-digital/*` | a `registries:` block for GitHub Packages, referenced by every npm entry |

`node_modules`, `dist`, `build`, `.git`, `.next`, `.yarn`, `.worktrees`, `.claude`,
`.stryker-tmp` and `.windsurf` are skipped.

The registry uses the `GHCR_TOKEN` **Dependabot** secret of the organization. Dependabot has its
own secret store: Actions secrets are not visible to it, and without the registry every private
tarball fails with `401`.

## Enable security updates on the repo

```bash
gh api -X PUT /repos/skylabs-digital/<repo>/vulnerability-alerts
gh api -X PUT /repos/skylabs-digital/<repo>/automated-security-fixes
gh api /repos/skylabs-digital/<repo>/automated-security-fixes   # {"enabled": true, "paused": false}
```
